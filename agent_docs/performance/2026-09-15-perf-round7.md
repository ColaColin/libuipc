# Perf round 7 — the constitutions no benchmark ever ran: dahl friction + plastic bending

Rounds 3–6 tuned the official four plus the round-6 tumbler. The TODO's own audit (PERF_METHOD §4,
"helpers that never reached their call sites") named the three shell-bending constitutions that **no
benchmark scene executes**: `DahlFrictionDiscreteShellBending` (zero callers in the repo at all; used
by `cloth-dataset`/`cloth-machine` outside it), `StrainPlasticDiscreteShellBending` and
`StressPlasticDiscreteShellBending` (C++ sim_case correctness tests only). A same-day coverage
survey confirmed only 5 of ~25 constitution families have benchmark callers, and that these three
kernels are the least-optimized in the bending family:

- the plain hinge ships `<Proj = 3 Gauss-Newton, Solver = 1 QL>` (round 6 s02/s19: −90 % kernel,
  −12 to −19 % end-to-end);
- dahl still launches with **runtime bools** and `Solver = 0` — Eigen's `SelfAdjointEigenSolver`,
  11 704 B stack frame, 255 registers, the largest in the family;
- the plastic variants call the bare dense `make_spd(H12x12)` — the +81.0 % / +19.4 % levers
  measured on the plain hinge's dense path apply to them verbatim.

Round 7 changes the workload again, in the TODO's own suggested shape: a **cyclic press creasing a
mixed stack** — denim (dahl), cardboard (strain-plastic), sheet metal (stress-plastic) — so those
kernels carry real benchmark load, then wires the proven hinge
machinery into the call sites that never had it. `NeoHookeanShell2D`, also unrepresented, is the
membrane for the carton/metal sheets.

- **Base**: tag `perf-round7-base` = `fce57589` (samples `2e52a52`).
- **Brief**: `/workspace/output/round7/AGENT_BRIEF.md`.
- **Box**: local RTX 2070 SUPER only (cc 7.5, 8 GB, FP64 1/32). **Serial**: one worker at a time.
- **Branches**: `perf/round7-sNN-<area>`, one step per branch cut from head at spawn, merged by the
  coordinator, step numbers assigned centrally at merge.
- **No acceptance box.** Every number here is cc 7.5; each accepted step records a transfer
  prediction (PERF_METHOD §6) a future rented run can falsify.

## s00 — the instrument

Scene: `libuipc-samples/examples/103_crease_press/` (next free number after
`102_net`). Evidence: `agent_docs/performance/data/2026-09-15-round7-s00/`.

**What it is.** A cyclic hydraulic press creasing a mixed stack of seven clamped
sheets — 3 denim (`StrainLimitingBaraffWitkinShell` + `DahlFrictionDiscreteShellBending`,

## s04 — the plastic Gauss-Newton Hessians: REJECTED by the regime gate (2026-09-16)

**The premise held.** Both plastic curvatures are non-negative on every

- **strain**: `ddEddθ = 2L0κ/h̄` is a *constant* — no yield-state dependence at

### The mechanism (the brief's "find out WHY before changing anything")

- **update_p_beta is AT the roof**: 1.61 MB in 3.68 µs = **438 GB/s = 97-98 %
  of the 448 GB/s DRAM peak** (its only FP64 is 1 DFMA/thread). A geometry
  change cannot add bandwidth.
- **update_xr is dual-constrained**: 2.82 MB in 8.2-8.4 µs = 75-77 % of the
  DRAM roof, with a **~4 µs FP64-issue floor underneath** — the SASS carries a
  full FP64 division per thread (`alpha = *d_rz / *d_pAp`: MUFU.RCP64H + 8
  DFMA + 2 DMUL + 1 DADD ≈ 12 FP64-class instructions × 50,334 threads on
  2 FP64 lanes/SM × 40 SM = 144-169 G instr/s). The two roofs overlap
  (max ≈ 6.3 µs) and the measured time is the overlap plus tail/ramp.
  Neither DRAM bandwidth nor FP64 lanes are geometry terms.
- **Occupancy is thread-limited and already full**: 42/32 registers → 1024
  threads/SM at any whole-warp block size; the grid (197 blocks at 256) covers
  the 40-SM machine 1.23x, and spreading to 128 keeps the **same 1576 warps =
  the same 1.23-wave quantisation** — round-6 s15's parallelism-limited
  precedent, verbatim ("halving the block size leaves the same warp count").
- **fused_dot is not a stream**: 0.80 MB in ~7 µs (114 GB/s) is a two-level
  reduction tree (14 DADD + 20 SHFL per thread) plus 197 same-address FP64
  atomicAdds; a block-size change would alter the tree shape (not
  bit-identical) and the spread contract excludes block-cooperative kernels.
- **Graph-replay launch overhead is real but small**: median inter-node gap
  **384 ns** inside a replay block; the `<<<1,1>>>` scalar node's 1.95 µs is
  mostly its own three serial dependent loads, not node overhead. And the
  per-launch average is not a contention artifact: the whole PCG chain runs on
  one stream, the working instances are tight (p10-p90 8.03-8.45 µs) and the
  only fast tail (1.4 % at 2.1-2.5 µs) is the post-convergence early-exit path.
  The vectors stream from DRAM because each iteration's SpMV pushes ~30 MB of
  matrix through the 4 MB L2 between the vector nodes.

## s08 — the K16 block assembly's dead triangle + mirrored back-assembly (2026-09-16)

**Diagnosis first (worker agent, evidence `data/2026-09-16-round7-s08/`).** The

(the 20-frame window `cwc_api` shows zero distribute kernels; the 100-frame
`cwc_full` kern_sum shows k1×728 / k3×1092 — a trap for anyone profiling an
early window of that scene).

Two findings kill the item:

1. **The recoverable part is zero.** The park is 96 %+ **drain** — the host
   waiting for contact part 1 / the radix sorts / the scan whose *output* it is
   about to read. During **every** `_distribute` round trip on both traced
   scenes some kernel was executing on another stream (K9 contact side stream,
   ABD prepass stream), so the D2H latency leaves the GPU busy:
   `stall(GPU-idle) = 0.00 ms` measured on both. The per-readback stall is
   5.9–6.6 µs — round 4's pinned staging already removed the 14–22 µs pageable
   penalty the TODO was written against. Even the raw park is under the
   brief's 0.5 % bar on both scenes (0.42 % / 0.46 %).
2. **The s14 wait-move does not transfer.** s14 deferred a *join* (a stream
   event); this is a *value* the host consumes. The classified count gates the
   downstream layout, not an ordering: `GlobalLinearSystem::build_linear_system`
   opens with `_update_subsystem_extent` (`global_linear_system.cu:787`), where
   every subsystem's `report_extent` reads `gradient_count()` /
   `hessian_count()` (the s14 accessors) to compute its block offset — sizing
   `triplet_A`, `bcoo_A`, every subview, FEM's `_assemble_dytopo_effect` launch
   geometry and ABD's `_prepare_dytopo_pairs`. Deferring the wait into those
   accessors moves the park by only the `receive()`-stash + `solve()`-entry
   host walk (single-digit µs — there is no GPU-launchable count-independent
   work in between; FEM G/H is layout-gated, round-6 s12's finding, and the ABD
   prepass is already forked inside the contact fork, s11 mode 4). Predicting
   the count cannot work: a wrong prediction is a wrong matrix layout with no
   fallback after the fact.

The TODO's part (b) — extending s14's deferred join to the multi-receiver
scenes — closes with the same evidence: the join at the converter
(`compute_dytopo_effect:223`) is a device-side data dependency of the
converter itself (it reads the collected buffers), not a host stall; moving it
later would race the sorts. What *would* unlock the s14-style overlap on these
scenes is a **fixed-slot staging restructure**: reserve each subsystem a
capacity-based slice of `triplet_A` (the contact upper bound N is host-known
from the reporter extent *before* assembly), let FEM/ABD assemble into fixed
offsets while contact+convert still run, and let the converter's `row >= 0`
filter drop the unwritten slots — it already exists for exactly this shape
(round-5 s26 kept the −1 index fills for it). That is a `GlobalLinearSystem`
layout change with a s14-scale prize (~1.3 % ms/Newton on case2 precedent) and
a big blast radius (every subsystem's extent contract, BCOO sizing, fill cost,
PCG graph stability) — recorded as a candidate, not attempted here.

**Gates.** Nothing ships, so the correctness gate ran at head as the box
health check: identical to `baseline_tests.txt` (11/3, 1112/36, 2730/46,
100/3, 4/1, 448/23, 14213/95, pytest 48+1 — duration string only). No A/B:
there is no knob because there is no change; the profiled runs above are the

**Candidates found while working (for s10+, with the evidence):**
