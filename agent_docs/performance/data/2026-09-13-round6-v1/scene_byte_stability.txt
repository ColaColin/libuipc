Scene byte-stability of the V1 perturbation knobs (round 6, 95_tumbler_garments)
================================================================================
The tumbler scene is this round's instrument; its default path had to stay
byte-stable while gaining an opt-in perturbation.  Proved, not argued:

1. Code: the only unconditional change inside the garment build loop is
   `for name, builder, yaw, y in GARMENTS` -> `for _gi, (name, builder, yaw, y) in
   enumerate(GARMENTS)`.  Both perturbations sit behind
   `if PERTURB_YAW != 0.0 and _gi == PERTURB_GARMENT` /
   `if PERTURB_VERTEX != 0.0 and _gi == PERTURB_GARMENT`, and both defaults are
   exactly 0.0, so with default flags `G.lay_flat(V, yaw, (0.0, y, 0.0))` is called
   with the identical `yaw` object it was called with before.
   `--vel-tol` likewise defaults to the literal 0.05 that was there.

2. Measured: the constructed initial cloth positions of the default scene, dumped
   from the edited main.py as float64, are **bitwise identical** (np.array_equal on
   the uint64 view, 9396 x 3 doubles) to the positions built by re-executing the
   un-edited construction (`tumbler_geometry.build_*` + `lay_flat` with the same
   arguments) in a standalone script.  See probe/f0_edited.npy.

3. End-to-end sanity: three-frame `--verify` summaries of the *un-edited* scene and
   of the edited scene under default flags differ by the same amount two runs of the
   un-edited scene differ from each other (r_max: orig-vs-orig 1.4e-8,
   orig-vs-edited 4.2e-9, edited-vs-edited 9.2e-9).

4. Correction to the round record, found here: s00's "frames 1-3 are bit-reproducible"
   holds for the *iteration counts*, not for the positions.  Two identical runs of the
   *un-edited* scene already differ at 1e-8 m in `r_max` by frame 3.  The scene has no
   RNG; the seed is GPU reduction order.  That is why arm A is itself a perturbation
   experiment and why the pooled A+A' reference distribution is the right null.

The perturbations used, and what they are worth at frame 1 (rms cloth-vertex
displacement against an unperturbed exact run, from the divergence analysis):

  two identical exact runs (GPU reduction order only)   1.2e-09 m
  --perturb-vertex=1e-9 / --perturb-yaw=1e-6            4.0e-08 m
  --perturb-vertex=1e-6 / --perturb-yaw=1e-5  (A'')     see divergence_n10.txt
  Gauss-Newton against exact (the change under test)    1.8e-07 m

d_hat in this scene is 1.27e-3 m and the element edge is 6.2e-3 m, so every one of
these is between 1e-6 and 1e-4 of the smallest physical length in the problem.
