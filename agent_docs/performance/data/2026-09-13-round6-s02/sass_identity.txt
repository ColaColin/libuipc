The arms of every A/B in this step are Proj1 Solver1 (UIPC_DSB_GAUSS_NEWTON=0,
the shipped default on main) and Proj3 Solver1 (=1). The old arm is
SASS-identical to main, so it reproduces main's binary exactly.

Proj1 Solver0 differs by register allocation only. Adding a seventh kernel to the
translation unit made ptxas re-allocate registers inside one cold rollback
instantiation (UIPC_DSB_REDUCED_SPD=1 + UIPC_MAKE_SPD_JACOBI=0), and the
measured difference is:

  * identical instruction count (15104 both),
  * identical FP64 stream: all 5441 FP64 opcodes in the same order,
  * 136 changed lines, all of them BRA/BSSY branch targets or LDL/STL
    widths (one 128-bit local move split into two 64-bit ones).

On the *previous* build of the same source the instantiation that jittered was
Proj0 Solver0 instead, which is the signature of whole-TU register-allocation
noise and not of a semantic change. Neither instantiation is reachable on a
default run, neither is an arm of any measurement in this step, and the shipped
Proj1 Solver1 is byte-identical in both builds.
