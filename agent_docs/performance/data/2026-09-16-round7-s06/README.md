Branch `perf/round7-s06-pcg-spread` from main `22e08654`. **No engine source
touched** — the binary is main's `c2a104b6` throughout (sha256 equal to s05's
start hash); every measurement ran on the unmodified build through the existing
round-4 `UIPC_PCG_BLOCK_DIM` knob, which reproduces the spread geometry exactly

GPU kernel time** — 8x below the brief's 1 % wiring bar and ~46x below
crease-press's end-to-end MDE. mas-bunny (±0.1 % envelope) reads the whole
geometry change at −0.10 %, overlapping. The round-6 TODO item ("the four PCG
vector-kernel sites were never checked for spreading") closes with this
measurement. Nothing ships; no transfer prediction to test.

## The mechanism in four lines

1. `fused_update_p_beta` streams 1.61 MB in 3.68 µs = **97-98 % of the 448 GB/s
   DRAM roof** — a geometry change cannot add bandwidth.
2. `fused_update_xr` streams 2.82 MB in 8.2-8.4 µs = 75-77 % of the roof with a
   **~4 µs FP64-issue floor underneath** (the redundant per-thread `rz/pAp`
   division: MUFU.RCP64H + 11 FP64 ops × 50,334 threads on 2 FP64 lanes/SM) —
   neither term is a geometry term.
3. Occupancy is thread-limited (42/32 registers): 1024 threads/SM at ANY block
   size; the grid (197 blocks at 256) already covers the 40-SM machine 1.23x,
   and spreading to 128 keeps the **same 1576 warps** = the same 1.23 waves —
   round-6 s15's parallelism-limited precedent.
4. `fused_dot` is a reduction (two-level tree + 197 serialized FP64 atomics),
   not a stream; a block-size change would alter the tree shape, and the spread
   contract excludes block-cooperative kernels anyway.
