Read the last two columns together. The union reads -0.4 % for the arm worth
-5.0 % of the wall, +4.2 % for an arm worth -4.8 %, and -4.3 % -- its best score
-- for the arm worth only -2.0 %. The per-arm sd of the union is 0.3-1.7 %,
while the arms are 4-9 percentage points apart on it, so this is not sampling
noise; and with 4-6 runs per arm it is not the single-run accident that s10's
one trace per arm could not exclude.

Two separate defects are stacked here:
  (a) the union is a LEVEL, and s10 compared levels across runs whose Newton
      counts differ. Normalising per iteration is necessary but not sufficient;
  (b) even normalised, the union measures GPU-busy time, which is not what these
      arms change. Every arm hides the same 155 ms of prepass; what differs is
      which kernel gets starved of SMs and whether that kernel is on the host's
      critical chain. The union cannot see a host stall at all, and under nsys
      the host stalls differently -- which is exactly the variable under test.

`cuda_gpu_kern_sum` was already known to be unusable for scene totals here (it
is a duration sum: sum/union is 1.08 off, 1.13 at mode 1 and up to 1.22 at mode
4). This adds the union to the list. For a step that changes *where* work is
issued, the instrument is the un-instrumented end-to-end benchmark at n>=20 with
a null arm; the trace is for MECHANISM only (which kernel ran when), and it is
very good at that -- see overlap_rwb.txt.
