## Rules for this round (each step = one agent, one commit)

1. One optimization per commit. Keep an env switch back to the old path where feasible
   (`UIPC_<NAME>=0`), so A/B runs use the same build.
2. Correctness gate before commit: `uipc_test_sim_case` aggregate, `uipc_test_backend_cuda`,
   `uipc_test_regression`, `uipc_test_core`, `uipc_test_geometry`, `uipc_test_common`,
   `uipc_test_sanity_check`, and `pytest -m "cuda and not example" python/tests`, all from
   `build-perf`. No new failures relative to the baseline table below.
3. Performance gate: measured on the targeted scope (uipc Timer scope or nsys kernel time) AND
   the official benchmark(s) it targets, before/after (or env A/B). Report Newton/PCG counts with
   every wall number. A change without a measurable gain outside run-to-run noise is reverted
   and recorded as rejected below.
4. Exact-arithmetic (bit-identical) or rounding-level-only changes preferred. Anything that
   changes iteration counts is an algorithmic change and must be justified separately.
